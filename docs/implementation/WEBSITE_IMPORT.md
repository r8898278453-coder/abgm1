# Website import foundation

11 November2026 IST. P04-02 in progress; earlier phase/dependency acceptance remains open. This batch provides a tested single-page snapshot transport, not a finished user-facing importer. No migration, existing scraper replacement or live website fetch was performed.

`fetchWebsitePage` accepts an HTTPS URL without userinfo, query, fragment, trailing hostname dot, IP literal or nonstandard port. Redirects must remain on the exact original origin; apex/www/subdomain alternatives require an explicit later ownership decision. All DNS answers must pass a conservative public-address policy, and one checked address is pinned directly into the TLS socket lookup with automatic family selection disabled. DNS is checked again on every redirect. TLS certificate verification uses the original hostname. Private, mapped, loopback, multicast and selected special/documentation ranges refuse; IPv6 is deliberately conservative, including refusal of the entire2001 and3fff prefixes. Some valid websites will therefore be unsupported rather than silently bypassing the guard.

Each snapshot has a total10-second deadline including DNS and redirects, DNS timeout at most3 seconds, max3 same-origin redirects and256KiB body limit enforced on streamed bytes as well as declared length. Only HTTP200 text/html or text/plain with identity encoding succeeds. The request sends fixed Accept/User-Agent headers, with no caller authorization/cookie material. The returned bytes are exact response bytes, not model-generated text. Network details are hidden behind fixed WebsiteImportError codes. Dependency seams are internal test hooks, never browser-supplied resolver/request configuration.

Mocked transport tests cover pinned DNS, mixed private/public rejection before dial, bytes/redirect provenance, cross-origin redirects, unsupported/compressed bodies, declared/streamed size refusal and private error redaction. They do not establish actual internet reachability, hostile site compatibility or Hostinger egress support.

Remaining implementation: authorize against the client's canonical registered website; durable source/run and original HTML provenance storage; persistent integration of the static extraction/preview described below; aggregate usage controls and robots/site policy; review/approval and structured facts; UI progress/partial failure, deletion and invalidation; queue/recovery; real egress and hosting acceptance. JS-rendered sites require an explicit partial/unsupported state unless a separately supported renderer is added. Never wire arbitrary browser URLs directly to this transport without canonical client authorization and rate/usage limits.

The product transport uses a directly pinned TLS socket. Actual deployment behind an outbound proxy needs an explicit tested design that preserves destination validation/pinning; current cloud tests mock transport and bypass no environment network policy. No real network request or claimed production deployment was made by these tests.

## Static extraction and preview runner continuation

parse5@8.0.0 now parses bounded HTML as inert data and decodes entities. UTF8/ASCII text only; unsupported charset/invalid bytes refuse. Script/style/template/noscript/SVG/canvas/iframe/object/embed/nav/footer/form trees and basic hidden/aria-hidden/inline-style exclusions are skipped. This is not browser-computed visibility or full content/fact verification. Parser traversal limits50000 nodes/depth256; normalized text128Ki characters. Source URL/title/original SHA256/text SHA256/byte size and bounded same-origin relevant links accompany text. Block boundaries are preserved.

previewWebsiteImport is an internal, unapproved in-memory preview: max3 page attempts including root, only starts fetches within20s of run start (each production fetch max10s), relevant links/about/contact/services/products/pricing/FAQ, private exact original byte copies and fetchedAt timestamps. Failed/empty/truncated imports are PARTIAL; zero-page failures UNAVAILABLE. Foreign returned origins refuse. No scripts execute, no API/UI endpoint calls this code yet, and no bytes or provenance are saved to SQL. Registered-client authorization, durable source/run storage, robots/site policy, review/approval, UI and hosting/egress acceptance remain required before user-facing enablement.
