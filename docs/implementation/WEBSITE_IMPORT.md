## Durable user flow

Knowledge view has **Import registered website**. POST `/api/companies/:id/knowledge/import-website` accepts only an empty object and responds202 with `{success,companyId,run,reused}`. It authenticates/authorizes the workspace, validates its saved company website and queues internal website_import work. Admission performs no DNS or HTTP fetch. Missing/unsupported website configuration refuses with409. Browser-supplied URLs, payloads and actors are never authoritative. The existing rate limiter applies.

Company-row locking serializes concurrent admission: one active QUEUED/RUNNING/RETRY_WAIT import per client. Repeated clicks or a lost acknowledgement reuse that active run. A different registered URL while an older run is active requires resolving/cancelling that run first. A new manual import after terminal completion creates a new run; this is not permanent deduplication of all future refreshes. Queue payload contains only the canonical website URL, not webpage bytes or extracted text. Public generic queue admission rejects the internal type.

The existing dispatcher/worker, database-clock lease, heartbeat, attempt/backoff budget, events/outbox and global stop are reused. Worker verifies its current persisted lease and rechecks the company's registered website before opening the fetch and again inside successful persistence. Deleted clients or changed/invalid saved websites cannot authorize stale results. Fetching runs outside SQL transactions; only bounded persistence holds row locks. Running cancellation or lease takeover prevents the old worker from committing snapshots/results. Cancellation cannot recall an already-open request.

Root and relevant same-origin about/contact/services/product/pricing/FAQ links are considered, max3 attempts. Static UTF8/ASCII HTML/plain text is parsed without JavaScript/resource execution. Empty, unavailable, partial and truncated outcomes remain explicit. No page saved is recorded as a failed run with UNAVAILABLE details, even though no source lifecycle event exists. Transient runner-capacity/unconfirmed persistence failures use bounded queue retries; permanent no-page failures require a new manual run. Fetch-start duplication after an expired lease is possible; source/result persistence is fenced. This is not a promise of exactly-once HTTP requests.

## Atomic originals, extraction and review

All fetched page originals, their source histories, fresh knowledge_extract jobs/events/outbox and the final import result commit in one transaction with the owning parent job. Failure on a later page or outbox write rolls the whole page group back. The retained queue lease/retry budget permits recovery; no successful/partial result is invented after an unknown commit. A subsequent actual state read determines what was committed.

Each successful page stores exact private original bytes, media type, original URL and fetch epoch milliseconds in knowledge_sources. Fresh sources are QUEUED and unapproved. Parent SUCCEEDED means snapshots were committed; it does not mean extraction, approval or business verification finished. Separate source jobs perform bounded parsing. Existing authenticated download, exact-revision review/approval/withdraw/delete and approved-only quoted search apply. Source retry uses saved bytes, retains provenance and clears approval; only a new import refetches current website content.

Company-wide content SHA deduplication remains: identical bytes reuse the first source ID, original URL/time and review state without another extraction job. A new URL/time is not invented for replay. Changed bytes create another unapproved source; old approved snapshots are not automatically withdrawn. Review contradictory content manually; structured key-based review/manual precedence is in KNOWLEDGE_FACTS.md; semantic conflicts and automatic snapshot supersession remain pending. Existing50-source/32MiB quotas apply to the atomic page group. Deleting a source does not erase the minimal historical run reference; deleting source bytes is not full audit/backups erasure.

## History and UI

GET `/api/companies/:id/knowledge/website-imports` returns the newest10 scoped run DTOs and nextBefore. Optional exclusive `before` is a known scoped run ID; unknown/foreign cursors return409, invalid/extra query fields400. Created-time/ID keyset ordering handles same-second runs. Each read uses the canonical5-second read-only SQL deadline and at most11 history rows (plus one cursor lookup). DTOs contain run/company ID, root URL, actual queue status/attempts, DB epoch times, fixed error code and bounded result metadata only. No source text, bytes, credentials or raw exception is returned. History is not backfilled for request-bound imports made before this feature.

POST `/api/companies/:id/knowledge/website-imports/:runId/cancel` accepts only `{}` and atomically cancels this client's active website import with its queue event/outbox. Foreign, terminal and changed runs refuse409. Cancelling a running import fences its eventual commit; already committed child extraction jobs are independent source operations and are not recalled.

Knowledge view loads/reloads/loads older run history, shows queued/running/retry/failed/cancelled/partial outcomes and permits active-run cancellation. Status and source cards refresh explicitly; no browser session needs to stay open for workers to operate. Async history/admission/cancellation completions are fenced on client remount. Source cards retain URL/time and extraction state. All new timestamps display canonical Asia/Kolkata IST. Failed/history-unavailable reads are not shown as successful imports.

## Transport and extraction limits

HTTPS only; no userinfo/query/fragment/nonstandard port/IP literal. Every DNS answer passes the conservative public-address policy. One checked address is pinned into the original-hostname TLS socket, automatic family selection disabled, TLS verification enabled. DNS is checked per redirect. Same-origin redirects max3; page total10s including DNS, DNS3s, streamed body256KiB, text/html or text/plain only, identity content encoding. No caller cookies/authorization forwarded. Exact private/special subnet checks allow unrelated public IPv4 and normal global2001 IPv6.

parse5@7.3.0 has explicit CJS/ESM exports for server.cjs. It treats entities/source content as inert text. Script/style/template/noscript/SVG/canvas/iframe/object/embed/nav/footer/form trees and basic hidden/aria-hidden/inline-style exclusions are skipped; browser-computed CSS visibility is not established. Traversal50000 nodes/depth256, normalized text128Ki characters. New production fetches start only within20s of run start, each bounded10s, max3 attempts. Preview capacity is one process-local active fetch runner; cross-instance total/per-site/global usage quotas remain separate work.

Product transport uses directly pinned TLS. Proxy-only egress requires an explicitly tested destination-safe design. Fixture-only network tests do not establish hosting access. Registered client URL is not proof of domain ownership/consent. Unsupported JavaScript-heavy pages need a text source or later supported renderer; OCR/rendering support must not be invented.
